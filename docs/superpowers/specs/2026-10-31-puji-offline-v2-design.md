# 铺记 Android 离线基础版全面升级

状态：设计提案，待用户确认；不代表已实现。
日期：2026-10-31。

## 1. 已确认的目标与边界

用户要求全面升级离线基础版，允许推倒重做 UI 和图标；视觉为苹果风格的精致、时尚、简约、明了，删除不必要的说明文字。本轮只升级 Android。未来可能扩展多设备协作，目前不引入账号、服务器或联网依赖。

主要服务小卖部店主：在柜台快速出货，在货架旁进货和盘点，核对库存和经营情况。保留“铺记”名称、中文界面、现有历史数据与单据快照。

成功标准：一单可包含多种商品；每次库存变化有依据；错误可追溯地纠正；备份可以真正恢复；原版覆盖升级不丢数据；主要页面没有教程式说明和无关装饰。

本轮不做：云同步、员工权限、多门店、在线支付、供应商及会员体系、赊账、打印、批次与保质期、称重及箱件换算、iOS 版、鸿蒙改动。默认人民币、整数件数。

## 2. 现状依据

- Android 配置为 1.1.1 / versionCode 5，SQLite 版本 2。
- 商品、入出货、经营汇总、CSV、危险操作确认已经存在。
- Android 扫码在首件识别后锁至成交，难以组成多商品订单。
- 商品编辑直接写库存，缺少库存调整依据；停用后缺少管理入口。
- 未知商品建档和首次入货分两个事务；需要统一。
- 查询、交易、统计部分在 Compose 回调中同步执行；顶层大量 remember 状态未持久化。
- 全量单据查询后再逐单查明细并在内存中统计，数据增长后有性能风险。
- 毛利润按商品进价快照；现金结余仅为销售收入减进货支出，不能作为完整现金账或净利润。
- 有 CSV 导出但没有完整恢复入口。系统 allowBackup 不代替用户可验证的备份流程。
- README、测试文档与实际版本不同步。

## 3. 方案取舍

用户已选择“离线单店全面升级”，并排除本轮鸿蒙升级。

### 采用：延续原生工程，重做界面和业务工作流

保留 Kotlin / Jetpack Compose / SQLite / CameraX / ML Kit。重组状态和数据层，增加明确的业务操作。可沿用历史数据和应用身份，减少迁移风险。

### 不采用：跨平台重写

会增加相机、数据库、数据迁移和安装包验证工作；当前只升级 Android，没有足够收益。

### 延后：云端协作版本

协作需要身份、服务端裁决、冲突处理和可用库存策略。现在仅预留稳定标识及服务接口，不将“有 UUID”等同于已经支持同步。

## 4. 视觉方向与文案

苹果风格作为精致度和信息层级的参考，Android 系统返回、权限、文件选择、分享、触控和无障碍仍使用原生习惯。

2026-10-31 修订：用户否决首轮蓝白界面，明确改为米白主色。新版采用米白 #F6F2E9 主背景、浅奶白 #FFFCF5 分组表面、暖墨色 #292C2A 主文字、暖灰 #6D6E69 辅助文字；灰蓝 #365D6C 用于主动作及选中态，淡金 #D9BA7C 只作图标和少量细节点缀，不承载低对比度正文。辅助文字从预览 #6F706B 轻微加深以满足米白背景小字号对比度。红色只用于风险和损失。深色模式单独配色，不反转图片。避免钴蓝主色、冷白大卡片、票据切口、橙绿争抢主色和粗重描边。

以分组列表与对齐的数字为主，减少等大卡片。根据用户对“字体太大、画面挤”的反馈，统一缩小并减轻字重：页面标题 22sp/600、分组标题 15sp/500、商品正文 15sp/400、行内价格 15sp/500、辅助字段 12–13sp/400、首页重点金额 26sp/500、次级金额 22sp/500、经营双列金额 21–22sp/500、按钮 14sp/500、底栏标签 11sp/500。中文与数字使用同一套系统 sans-serif 字族与统一字重映射；金额采用等宽数字特性，不用等宽字体包装全界面。默认不使用 700–900 粗黑字重，不通过夸大标题制造层级。

四页共用上述角色，不单独放大某页标题。正文行高约 22sp、辅助文字约 18sp，页面左右留白 20–22dp，分组间距 24dp，列表行高约 68–72dp，信息对齐而非紧贴。扫码预览压缩至约 180dp，为清单和结算留空间。点击区域仍至少 48dp，不随字号一起缩小；字号使用 sp 并尊重系统字体缩放。图标使用统一矢量线条，不再用 Unicode 字形充当图标。

本轮排版参考 Things 的列表节奏、Craft 的文字与空间层级，以及 Apple 的可读性建议；这里只提取通用原则，不复制它们的字体资源、品牌或页面。生成图为视觉方向预览，实际字号、点击区域、大字体和长金额适配需在 Compose 实现后验证。

首轮商品照片并非既有业务数据，也不代表新增商品图片功能。修订预览去掉杂乱商品缩略图，以商品文字、轻量分类符号及对齐的价格和库存呈现。界面结构同时重做，而非只替换上一轮配色。

常用动作直接写“入货”“出货”“保存”“完成盘点”；删除中英文双标题、寒暄、重复功能介绍和常驻操作教程。错误、库存不足、恢复覆盖和清除等信息仍要清楚说明后果与下一步。金额单位、进售价含义、负值符号不能为简洁而删掉。

材质只在必要的导航或弹层表现层次，商品列表和报表不使用大面积玻璃。动效短且有目的；尊重系统关闭动画。

## 5. 页面结构

保留四栏，调整名称为“今日、商品、扫码、经营”。设置从今日右上角进入；备份和清除移入设置，不占据经营首页。

### 今日

顶部为页面标题与设置。首屏给出今日销售与毛利润、入货/出货入口、待补货列表；库存总值和最近交易放在后面。点击指标可到对应范围流水；待补货进入低库存商品列表。首次正式使用为空白状态，不自动混入示例商品；示例只在独立预览材料中展示。

### 商品

搜索、类别筛选、全部/低库存/停用筛选、添加按钮。紧凑商品行显示名称、售价、库存；进价进入详情，避免列表信息争抢。商品详情包含编辑、进货、出货、盘点、库存变动历史、停用与恢复。无条码商品支持手动创建和选货。

商品表单只管理资料和价格，不再直接改已有库存。新增商品可登记“期初库存”，生成可追溯期初记录，不算采购支出。停用商品不能交易，历史单据继续可读；停用前显示剩余库存，库存总值按实际存货统计，不能因停用消失。

### 扫码与订单

顶部切换入货/出货，紧凑相机区域，下方清单，底部固定件数、金额和确认按钮。支持相机、手工条码、搜索选货，修改数量、单价和备注，删除清单行。

识别已知商品后加入当前单据并继续扫描；同一条码在连续画面停留时只加一次，必须离开识别区并重新进入或明确再次添加，避免仅靠固定延时造成连加。多商品自动合并数量，声音/轻触反馈可关闭。

未知条码暂停相机，显示快速建档。入货模式建档后加入当前单据；建档与该次首次入货应在最终确认时同一事务提交，不提前记一笔入货，也不清掉原清单。出货模式未知商品默认提示先入货，避免凭空建立可售库存。

切换交易模式且清单非空时明确提示，不能悄悄丢弃。草稿自动保存到本地，退出或进程重建后可恢复；草稿只保存数量、意向价格和商品标识，提交时重新校验库存及商品状态，价格变更必须提示。提交期间禁止重复操作，成功清空草稿，失败保留全部内容。

### 经营与流水

月/季/年筛选、周期前后切换、收入与采购支出趋势、毛利润、进销差额、交易笔数，以及流水入口。将“现金结余”改为“进销差额”，避免暗示真实账户余额；不称毛利润为净利润。

流水支持日期、类型、商品/单号搜索和单据详情，分页加载。筛选条件同时用于页面和 CSV，导出文件名包含范围与类型，无结果不生成空表。详情展示成交价格、成本、原单和退货/冲正关联。

### 设置与数据

完整备份、恢复备份、商品 CSV 导入、库存/流水导出、扫码反馈、关于、清除数据。没有可恢复备份时提示用户先备份；永久清除保留长按两秒和清单说明。

## 6. 库存与异常处理规则

所有库存变动均来自业务单据，包含期初、入货、出货、销售退货、进货退货、盘盈、盘亏、报损、冲正。资料编辑不写库存。单据、明细、余额、库存流水、草稿提交标记在同一事务中更新。

库存不为负数；提交时在数据库内重新校验。金额为整数分，数量为正整数，有界输入并检测乘法/累计溢出。每次提交生成稳定请求 ID，唯一约束避免重试重复入账。

盘点输入实际数量，提交时保存系统数量、实点数量、差额和原因。若盘点期间库存已有变化，则要求重核，不静默覆盖。报损单独记录数量、成本和原因，不混入销售额或采购额。

销售退货从原单选择商品和数量，可部分退货，累计不能超过原销售减去已退数量；按原单售价退款，按原成交成本回补库存。进货退货同样关联原入货并检查可用库存。没有原单的退款不在本轮范围。

原始单据不可直接编辑或删除。错单先生成关联冲正，再以新单重录；已部分退货的原单不能全单冲正，先处理关联退货。冲正若会导致负库存则拒绝并提示处理依赖。清除全部数据仍为独立危险操作。

## 7. 成本与报表口径

提议从新版本开始使用移动加权平均库存成本。售价与“建议进价”仍是商品字段；实际入货单价决定库存成本，不让修改建议进价追溯改变历史利润。

每商品保存整数分库存总成本和数量；出货按总成本与数量分摊，最后一件消耗剩余成本，避免累计舍入误差。单据明细保存整行成本及单价快照；退货基于原单成本按累计比例分摊、最后一次归还余数，避免多次退货累计超出原成本。

销售收入扣除销售退货与相关冲正；采购支出扣除进货退货与相关冲正；毛利润为净销售减净销售成本；进销差额为净销售减净采购；报损/盘亏成本单列，不伪装成销售毛利。退货与冲正计入发生当期，原成交历史保留。

进货退货和入货冲正按原单价格减少采购支出，但按当前移动平均成本减少库存价值，两者差额保存为独立的库存估值差额，不扣出负库存总成本、不混入销售毛利润。出货冲正按原单销售金额与实际成本恢复；已有关联退货时按前述依赖规则拒绝整单冲正。退货、冲正、盘点均保存此次库存成本变化与业务金额，不能只保存单价。

新增商品期初库存必须确认单位成本，默认建议进价；盘盈有存量时默认当前平均成本，无存量时默认建议进价，均展示可确认的单位成本。允许明确确认零成本，不静默把缺失成本当成免费。盘亏、报损按当前成本分摊出库；上述变化均不记采购现金支出。

旧单据快照不重算。直接从 v1 升级时，使用原历史规则回填成本并标记“历史估算”；v2 已有快照继续保留，但因旧结构没有来源字段，统一标记“历史口径，来源未记录”，不声称能够区分早先迁移估算和实际快照。迁移时现存库存成本以当前数量乘商品进价作为期初估值，保存迁移来源，不伪造历史采购单，也不补记现金支出。

## 8. 备份、恢复与商品导入

完整备份采用跨实现可读取的版本化 JSON 归档，包含商品、单据、明细、库存流水、必要设置、数据结构版本、导出时间、行数和校验信息。CSV 是查账和批量商品录入格式，不替代完整备份。

使用系统文件选择器保存，不申请全盘文件权限。保存成功后才更新“最近备份”；同机自动轮换备份只防操作失误，不宣称能够抵御卸载或设备丢失。可提示上次外部备份日期，不打断每次交易。

恢复采用“替换当前数据”，本轮不做混合合并。先验证文件大小、版本、校验、唯一 ID、关联完整性、金额数量范围，在临时库校验成功；显示日期、商品/单据数量与覆盖后果，恢复前创建当前数据回退副本。最终事务替换业务数据，任何失败保留原数据；成功后清掉旧草稿与筛选并统一刷新。

商品 CSV 导入提供模板和预览，逐行报告错误；按条码识别冲突，空条码不能误合并。默认只创建商品和更新资料；已有商品不能用 CSV 覆盖库存。新商品初始库存生成期初记录。禁止将流水 CSV 当商品表或完整备份导入。

## 9. 架构与未来协作边界

UI 负责展示和操作；ViewModel + StateFlow 持有状态；应用服务封装交易、盘点、退货、备份；Repository 管理查询与事务。数据库、文件和统计放到后台执行，避免阻塞主线程。一次成功写入触发统一数据失效更新，前台恢复和跨日时刷新今日与自然周期。

保留现有数字主键，同时增加稳定 UUID、操作请求 ID、版本及创建/更新来源字段；迁移只回填一次。库存流水与单据保持可追加，商品停用使用软状态。设计 Repository 接口供未来同步层接入，但不新增网络请求或空的“同步中”页面。

报表优先 SQL 聚合，流水分页并批量读取明细；增加日期/类型、商品流水、原单关联和稳定 ID 索引。无需为了本轮升级更换 SQLite 框架。

## 10. 图标与资源

设计方向（按用户最新澄清修订）：只借鉴参考图的简单几何图形/纸片拼接手法，图案与配色重新设计，不照搬爱心、星芒、翅膀或开口箱，也不要求图标与米白 UI 同色。当前探索为几块纸片拼成的小店门面，使用独立的杏色、陶土色与低饱和橄榄色方案；这是设计提案而非用户已选择的配色。移除首轮深蓝底与扫描框符号，不使用文字、细密条码、复杂插画或多主题拼接。先审阅方向预览，正式资源适配 Android adaptive icon 的前景/背景、安全区域及 monochrome 层；检查圆形、圆角方形和小尺寸。图像生成预览不是矢量母版，正式资源另行制作。

界面示意图仅为设计预览，不当作运行验收截图；正式验收来自独立 Android 模拟器或本任务可用设备。

## 11. 旧版升级与发布

维护 cn.puji.app 包名，提升 versionCode，数据库采用新增迁移而非删表重建。逐一验证 v1→新版和 v2→新版；旧价格、名称、时间、数量、停用状态、单据快照保持，迁移期初估值单独标记。

覆盖安装须核对旧 APK 与新 APK 的证书一致；当前 release 使用开发签名，不能在找不到原签名时要求卸载来假装完成升级。使用含真实结构的测试数据副本，不在用户生产数据上尝试迁移。

更新 README、测试记录、数据口径、版本说明和安装包信息。发布前先做可恢复备份，再在测试设备验收覆盖安装。

## 12. 验证与并行任务避让

仅本任务独立工作区写入；不修改原目录和鸿蒙工程，不清理其他工作区、共享缓存，不终止其他进程。构建串行、限制 worker；不复用或改变其他任务模拟器的字体、主题、账号及应用状态；忙时延后设备验收。需要设备时单独创建并明确指定本任务设备。

需要覆盖：多商品扫码、同码停留/重新进入、未知商品与原清单、手工选货、进出货切换、草稿恢复、重复提交、库存变化重校验、全部事务回滚、部分退货上限、冲正依赖、盘点冲突、成本分摊尾差、跨日/跨年统计、迁移和备份恢复、损坏文件与导入冲突。

UI 验收包括窄屏、长名称、大金额、键盘、1.3 倍字体、浅/深色、空/加载/错误/无权限状态，真实设备系统返回和相机权限。自动检查通过后，在独立设备验证：建档→进货→多商品出货→部分退货→盘点→导出→备份→恢复→核对，再验收旧版覆盖升级。

本轮审查已知测试环境限制：Gradle wrapper 在现有权限下无法写入用户目录；鸿蒙 Node 测试与 Node 26 的类型转换模式不兼容。后者不属于本轮 Android 修改范围。尚未运行新版构建，不承诺已通过。

5. 迁移/恢复/覆盖安装/设备验证，交付 APK 和说明。

阶段顺序是风险控制安排；最终交付为统一新版，不把仅换皮的安装包称作全面升级完成。

## 14. 参考与适用范围

- Open Source POS：https://github.com/opensourcepos/opensourcepos 。参考其销售、入货、交易留痕和库存业务组织，不复制其 PHP/Web UI，也不照搬复杂多用户模块。
- InvenTree Stock Tracking：https://docs.inventree.org/en/stable/stock/tracking/ 。参考库存调整自动留痕及变更分类。
- Apple Materials：https://developer.apple.com/design/human-interface-guidelines/materials 。参考内容层与导航层的清晰分层、材质克制使用。
- Apple App Icons：https://developer.apple.com/design/human-interface-guidelines/app-icons 。参考少量形状表达核心含义和小尺寸辨识度，Android 资源仍按 Android 适配。

以上业务和视觉选择是本次提案，不把外部项目的能力当作铺记现有能力。
